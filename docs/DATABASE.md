# BookFlow Database Schema

This document outlines the core entities and architectural patterns of the database.

## Core Architecture
- **Provider**: PostgreSQL (hosted on Neon)
- **ORM**: Prisma (v5.x)
- **Auth Linking**: Users are authenticated via Clerk. The `User` model maps directly via `clerkId`.

## Audit & Soft Delete Pattern
To ensure absolute data traceability, BookFlow implements a rigorous audit system:
1. **Soft Deletes**: 
   All primary models (`Service`, `AvailabilitySlot`, `Booking`, `Payment`, `Review`) include:
   - `isDeleted` (Boolean, default: `false`)
   - `deletedAt` (DateTime, optional)
   Records are never hard-deleted to preserve historical integrity.
2. **Edit History Tracking**:
   Every primary model has an associated `EditHistory` table (e.g., `BookingEditHistory`, `ServiceEditHistory`).
   - Tracks the `oldContent` as `Json` (capturing the state of the record *before* the modification).
   - Tracks the `editDate` and the `order` of edits.

## Core Models
1. **User**
   - Central identity for the system. Defines the `Role` (`CUSTOMER`, `PROVIDER`, `ADMIN`).
2. **ProviderProfile**
   - The business entity profile (name, category, location, rating). Linked 1-to-1 with a `User`.
3. **Service**
   - The offerings of a provider (duration, price). Tracks edit history and soft deletes.
4. **AvailabilitySlot**
   - The atomic unit of time generated by a provider. Supports `recurringRule`.
5. **Booking**
   - The transaction record linking `User`, `ProviderProfile`, `Service`, and `AvailabilitySlot`. Includes extensive statuses (`PENDING` to `COMPLETED`).
6. **Payment**
   - Manages Stripe references, platform fees, and provider revenue tracking.
7. **Review**
   - Standard 1-5 rating system with comments linking customer and provider.
8. **AdminActionLog**
   - Immutable append-only log tracking system-level administrative overrides and actions.
